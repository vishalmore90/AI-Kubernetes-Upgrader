Documentation & Architecture

A 17-step automated pipeline evaluating Kubernetes cluster upgrade safety before execution.

Assessment Methodology

Production Kubernetes upgrades frequently fail from unnoticed API deprecations, incompatible admission webhooks, or legacy storage provisioners. This engine analyzes every cluster subsystem against a curated release database.

1. API Lifecycle Verification

Scans active resources against scheduled removals across minor and intermediate versions.

2. Webhook & Controller Matrix

Evaluates validating and mutating webhook failure policies that could lock the control plane.

3. Storage & Runtime Plugins

Identifies deprecated in-tree storage provisioners and CRI runtime version requirements.

Engine Architecture

The system isolates analysis from cluster mutation. It operates in read-only and offline modes to preserve infrastructure stability.

Command-Line Interface

Run assessments directly in CI/CD pipelines or local workstations with zero external services required. 

# Run offline sample assessment
k8s-upgrade-assess assess --source 1.27 --target 1.30 --sample

# Assess from an exported cluster JSON snapshot
k8s-upgrade-assess assess --source 1.27 --target 1.30 --snapshot cluster.json

# Launch local web interface
k8s-upgrade-assess serve --port 5000
